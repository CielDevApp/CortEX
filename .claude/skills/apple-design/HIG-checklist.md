# HIG 検査基準 (公式 Human Interface Guidelines 抜粋)

出典: developer.apple.com/design/human-interface-guidelines (2026-07-21 取得、motion/gestures/buttons/feedback 章)。
**田中指定によりこれが最上位の正典**。apple-design スキル (WWDC 由来) と矛盾したら HIG が勝つ。

## Motion
- モーションは目的を持って足す。「動くから足す」は禁止。過剰なモーションは不快感を生む
- **高頻度の UI 操作にはモーションを足さない** (システム標準の控えめなアニメで十分)
- **モーションは任意化する** (Reduce Motion)。モーションを唯一の情報伝達手段にしない
- フィードバックモーションは「短く・正確に」。簡潔なほど情報が伝わる
- **モーションはキャンセル可能に**。アニメ完了を待たせない (中断可能性)
- 空間的整合: 上から出た view を横に払って消させるような不一致は混乱を生む

## Gestures
- ジェスチャは常に複数の代替手段と併存させる (ジェスチャを唯一の経路にしない)
- 標準ジェスチャの意味を変えない。独自ジェスチャで標準動作を置き換えない
- **できる限り即応** し、ジェスチャ中も継続的にフィードバックする
- **ジェスチャが使えない時はそれを示す** (無反応はフリーズと誤解される)
- ショートカットジェスチャは標準導線の補助であって代替ではない (Back ボタンは残す)

## Buttons
- **ヒット領域は最低 44×44pt** (視覚サイズでなくタップ可能領域)
- **カスタムボタンには必ず press state** (無いと無反応に感じる)
- 目立つスタイルのボタンは1画面に1〜2個まで
- 優先choiceの区別は「サイズでなくスタイル」で
- 破壊的アクションに primary role を与えない

## Feedback
- フィードバックは複数モダリティで (色+テキスト+音+haptic) — アクセシブルに
- ステータスは押し付けず文脈内に置く。アラートは本当に重要な時だけ
- 予期しない不可逆なデータ損失の前だけ警告 (予期される削除には出さない)
- 失敗した時こそ理由を伝える (成功は基本静かに)
